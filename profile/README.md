<h2>检测的目标是拿到三个可核对的字段</h2>
<p>检测一条地址是否属于 ISP 住宅，不需要复杂工具，核心是拿到三个字段：ASN（自治系统号）、运营商名称、地址类型标记。三个字段一对照，结论基本就出来了。剩下的路由追踪与行为测试，是用来确认「没有被包装过」的补充验证。</p>
<p>把检测目标定成「三个字段」，比定成「判断真假」更好执行，也更容易复核。</p>

<h2>三个字段怎么看</h2>

<p>三项里，ASN 最可靠。运营商名称可以被改，类型标记在不同库里可能不一致，但 ASN 的归属是注册机构分配的，改不了。</p>

<h2>ASN 怎么查</h2>
<p>用地址查询工具输入该 IP，结果里会显示 ASN 编号与名称。看到「AS」开头的编号，再对照名称是否为当地运营商。</p>
<p>判断要点有两个。一，ASN 名称是否为电信、宽带类运营商，而不是云服务或托管商。二，该 ASN 是否与标注国家一致。跨国的 ASN 出现在标称本地的地址上，是明显异常。</p>

<h3>为什么 ASN 比反向解析更可靠</h3>
<p>反向解析可以配置，配置成什么取决于地址持有者。有些机房地址也会配置看起来像住宅的反向解析。ASN 则绑定在注册层面，不是想改就能改。</p>
<h3>关于「双 ISP」的判定</h3>
<p>不同数据库对同一 ASN 的分类可能不同。查三个以上数据源，结果一致时可信度高；结果矛盾时，说明该地址处于判定边界，风险高于一致的情况。</p>

<h2>类型标记怎么查</h2>
<p>多数地址查询工具会给出类型字段，取值包括 ISP、residential、hosting、business、education 等。理想值是 ISP 或 residential。</p>
<p>需要注意的是，同一个地址在不同工具里可能给出不同类型。这是因为各家的数据源与更新频率不同。做法是查三个以上，以多数为准。</p>

<h2>补充验证：路由与行为</h2>
<p>路由追踪看路径是否落在标注国家境内。若绕经第三地再回来，说明链路不原生，延迟也会偏高。</p>
<p>行为测试看访问目标服务时是否触发额外验证。同一设备、同一浏览器、同一时段，分别用新地址与已知正常的地址访问，对比结果。只在一条地址上测，无法判断是地址问题还是环境问题。</p>

<h2>检测的执行顺序</h2>
<p>第一步，查 ASN 与运营商名称。第二步，查类型标记，多库交叉。第三步，查地址段规模，判断是否为集中的大段。第四步，路由追踪。第五步，行为测试。</p>
<p>前两步几分钟就能完成，能排除大部分问题。后三步耗时更长，用于确认边界情况。</p>

<h2>常见误判</h2>
<p>误判一，只看类型标记不看 ASN。标记可以不一致，ASN 不会。</p>
<p>误判二，只看一个数据库。单库结果可能过时。</p>
<p>误判三，把「有反向解析」当成住宅证据。反向解析可以人为配置。</p>
<p>误判四，用一次行为测试下结论。环境影响很大，需要对照。</p>

<h2>把检测结果做成一张可对比的表</h2>
<p>每测一条地址，就把 ASN、运营商、类型标记、段规模、路由落点五项记一行。攒够五条之后横向一看，规律会自己浮出来：哪家供应商的段更分散、哪家的类型标记更一致、哪家的路由更干净。这比一条一条凭感觉判断准确得多，也比听对方介绍靠谱。</p>
<p>这张表还能当作验收依据。放量之后抽检新批次，与首批数据对比，质量有没有下滑一目了然。没有基线时，质量下滑只能靠「最近好像问题变多了」这种模糊感受来察觉。</p>
<h2>常见问答</h2>
<h3>没有工具怎么查</h3>
<p>用公开的地址查询服务即可，输入 IP 就能看到 ASN 与运营商。多个服务交叉比对。</p>
<h3>查出来是 business 能用吗</h3>
<p>能连，但类型与住宅不同。需要住宅身份的环节，效果会打折。</p>
<h3>结果互相矛盾怎么办</h3>
<p>以多数为准，并优先相信更新更频繁的数据源。矛盾本身说明该地址判定不稳定，风险偏高。</p>
<h3>检测能代替试用吗</h3>
<p>不能。检测判断类型，试用判断稳定性与验证频率。两者互补。</p>
